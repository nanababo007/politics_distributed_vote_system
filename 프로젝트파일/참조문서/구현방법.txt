암호화 없이, 회의 안건별로 보기를 생성해서, 투표를 하고, 
선택 번호별 투표건수, 기권수, 미참여건, 참여구성원 정보/미참여구성원정보 등의 데이터를, 
데이터가 생성될때, 여러 서버에 동기화 되어 api 를 통해서, 데이터베이스가 동기화 되면서, 
여러서버에 저장되는 방식의, php 나 자바 솔루션

------------------------------

요구사항(암호화 없음, 안건별 보기, 상세 통계 및 미참여 구성원 추적, API 기반 실시간 다중 서버 DB 동기화)을 완벽하게 하나의 패키지로 묶어 판매하는 기성(Commercial) 솔루션은 찾기 어렵습니다.
대부분의 상용 투표 솔루션은 블록체인이나 암호화를 통한 '비밀 투표'를 핵심 기술로 내세우는 반면, 요청하신 스펙은 "누가 참여하고 안 했는지 투명하게 추적하는 실시간 데이터 동기화 시스템"에 가깝기 때문입니다.
따라서 이 요구사항은 기성 제품을 사기보다는 Java(Spring Boot)나 PHP(Laravel) 프레임워크를 기반으로 오픈소스 인프라를 조합하여 아키텍처를 구성(구축)하셔야 합니다. 구현을 위해 어떤 기술 조합과 솔루션을 활용해야 하는지 정리해 드립니다. [1] 

------------------------------

## 1. 요구사항별 구현 및 추천 기술 조합

## ① 안건별 보기 및 투표 데이터 구조 (Java / PHP 동일)

* 데이터 모델링: 암호화가 없으므로 RDB(MySQL, PostgreSQL) 테이블을 직관적으로 설계할 수 있습니다.
* 안건 테이블, 선택지 테이블, 투표 이력 테이블(구성원 ID, 선택 번호, 투표 시간), 기권 이력 테이블
* 통계 데이터: 투표가 발생할 때마다 전체 구성원 목록과 비교하여 선택 번호별 건수, 기권수, 미참여건(=전체 구성원 - 참여자), 참여/미참여 구성원 상세 정보를 실시간 집계(Group By 또는 스케줄러)하여 API로 서빙합니다.

## ② 여러 서버에 데이터가 생성될 때 동기화하는 방식 (핵심)
"데이터가 생성될 때 API를 통해 여러 서버의 DB를 동기화하고 저장하는 방식"을 충족하려면 개발 프레임워크와 데이터베이스 단에서 다음과 같은 솔루션을 조합해야 합니다.
## [추천 1] Java (Spring Boot) + 분산 이벤트 구조
가장 안정적이고 대규모 트래픽 분산 처리에 특화된 조합입니다.

* 프레임워크: Spring Boot
* 동기화 방식 (이벤트 기반): 하나의 서버에서 투표 API가 호출되어 DB에 저장되는 순간, Apache Kafka나 RabbitMQ 같은 메시지 브로커로 "투표 생성 이벤트"를 발행(Publish)합니다.
* 결과: 다른 여러 대의 서버들이 이 이벤트를 구독(Subscribe)하여 각자의 데이터베이스에 API 또는 내부 로직을 통해 데이터를 즉시 동기화합니다. 가장 확실한 실시간 다중 서버 동기화 방식입니다.

## [추천 2] PHP (Laravel) + 실시간 동기화 아키텍처
빠른 개발과 상대적으로 가벼운 시스템을 원할 때 적합합니다.

* 프레임워크: Laravel
* 동기화 방식: 라라벨의 내장 기능인 Job Queue(큐 시스템)와 Event/Listener를 활용합니다.
* 결과: 특정 서버에서 투표 데이터가 생성되면, 비동기 큐가 작동하여 미리 지정된 다른 서버들의 '데이터 동기화 수신 API'를 호출(Http Client 요청)하여 여러 서버의 DB에 데이터를 동기화합니다.

------------------------------
## 2. API 동기화 외에 고려해 볼 만한 데이터베이스 자체 솔루션
만약 애플리케이션(Java/PHP) 레벨에서 일일이 API로 동기화 코드를 짜는 것이 부담스럽다면, 데이터베이스 솔루션의 동기화 기능을 쓰는 것이 훨씬 효율적입니다.

* MySQL / PostgreSQL Replication (복제):
* 쓰기(Write) 전용 마스터 서버에 데이터가 들어가면, 여러 대의 슬레이브(조회용) 서버로 실시간 데이터가 복제되는 방식입니다.
* Multi-Master Replication (Galera Cluster 등):
* 어떤 서버의 DB에 데이터를 넣어도 모든 서버의 DB에 실시간으로 양방향 동기화가 일어나는 데이터베이스 솔루션입니다.

------------------------------
## 요약 및 제언
솔루션을 통째로 구매하는 것보다는 Java Spring Boot(또는 PHP Laravel) 웹 애플리케이션 프레임워크를 베이스로 삼고, 요구하신 통계 기능(기권, 미참여 추적)을 비즈니스 로직으로 구현한 뒤, 여러 서버 간의 동기화는 API Webhook 방식이나 메시지 큐(RabbitMQ 등)를 얹어서 시스템을 구성하는 것을 강력히 권장합니다.
현재 사내에 자바(Spring)와 PHP 중 어느 쪽 개발 리소스가 더 편하게 확보되어 있으신가요? 기술 스택 확정에 도움을 드릴 수 있습니다.
